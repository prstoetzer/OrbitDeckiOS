Overview

OrbitDeck is a native SwiftUI application for iPhone and iPad (iOS/iPadOS 17+). It computes satellite passes, Doppler, look angles, footprints, link budgets, and a large set of orbital-analysis and operating tools entirely on-device from live orbital elements. It is a companion to the OrbitDeck desktop app and CardSat by Paul Stoetzer, N8HM.

The design is deliberately simple: one observable store holds all state, a set of pure engine types do the math, thin service types fetch data, and SwiftUI views render it. There is no external app framework, no database, and one third-party library.

State & persistence

OrbitStore is an @MainActor final class OrbitStore: ObservableObject, created once in OrbitDeckIOSApp and injected as an @EnvironmentObject. It owns the satellite catalog, the selected satellite, favorites, space-weather snapshot, the reverse-geocoded location entity, and the operator's preferences.

StorePreferences is a single Codable struct (observer site, favorites, minimum elevation, GP source, per-satellite calibrations, location mode, the local-time flag, and more). Its didSet encodes to JSON in UserDefaults, so every setting is persisted the moment it changes. New fields are added as Optional so older stored blobs keep decoding without a migration step. Secrets (QRZ/Space-Track passwords) go to the Keychain, never the preferences JSON.

Because there is exactly one store and it is @Published, any screen reflects a preference change immediately, and the app has no separate "reload" plumbing — SwiftUI re-renders what changed.

Propagation engine

All orbital math funnels through OrbitPredictor, which wraps SatelliteKit. A SatelliteRecord carries a SatelliteKit Elements value; OrbitPredictor builds a Satellite(elements:) and asks it for position/velocity at a Julian date, then derives everything else:

  • look(_:observer:at:) — topocentric azimuth/elevation/range/range-rate, the sub-point (lat/lon/alt), sunlit flag, beta angle and footprint radius.
  • predictPasses(…) — a coarse rise/set scan with bisection refinement, handling in-progress and continuously-visible (high-orbit) passes.
  • groundTrack(…), subpoint(…), skyPath(…), currentOrNextPass(…).
  • dopplerFrequencies(…) — downlink/uplink dial frequencies with an optional calibration term.
  • footprintRadius(altitudeKm:) — the 0°-elevation surface radius, Re·acos(Re/(Re+h)).
  • OrbitDecayModel — a King-Hele decay integrator used by the orbit-lifetime and debris-compliance tools.

The engine types are pure and Sendable, so heavy work runs off the main actor via Task.detached and only the result is published back.

Live-update pattern

Live screens (Home, Track, Sky Radar, Ground Track, OSCARLOCATOR, Workable) refresh once per second. The reliable driver is SwiftUI's TimelineView(.periodic(from:by:)): each tick recomputes the current look/sub-point from the true tick time and redraws, while the surrounding view (and any Map camera or gestures) is preserved. Ad-hoc Task.sleep loops proved unreliable on device, so the codebase standardizes on TimelineView, anchored to a stable date so frequent re-renders don't re-fire it faster than 1 Hz.

Two related techniques recur:

  • Render-time memoization. Expensive but occasional work (e.g. the Home sky-track arc) is computed inside the TimelineView and cached in a reference held in @State, recomputed only when its inputs change — so it always draws without depending on a cancellable .task.
  • Stable location keys. While following the device, the raw GPS jitters. Reload keys round the position to ~100 m (coarseKey) or ~1 km (stableKey) so a moving fix doesn't thrash multi-second recomputes (pass lists, the Daily Schedule).

Navigation & UI

RootView is a NavigationSplitView: a sidebar of grouped destinations and a detail pane. Every screen is a case of the OrbitDestination enum (title, SF Symbol, whether it uses the selected satellite), and destinationView(_:) maps a case to its view. The detail pane caps reading-oriented screens to a comfortable width on iPad and lets full-bleed visual screens (globe, radar, ground track) use the whole pane; it also resolves a transient nil selection to the last real screen so it never flashes Home.

Shared UI lives in AppTheme (the ODTheme color palette, MetricRow, SectionCard) and Components (ODFormat, the selected-satellite header, the pass-alarm button, polar plots, and small helpers such as a center-snapping slider binding).

Time formatting

ODFormat centralizes date/number formatting. A single useLocalTime flag (mirrored from the store) switches every displayed time between UTC and the device's local zone; the local formatters honor the device's 12/24-hour preference, while UTC stays 24-hour by convention. primaryClock/secondaryClock render a time in the chosen zone and the other zone, which the pass lists use to show both at a glance. Tiny BASIC deliberately ignores the flag and always uses UTC.

Location & DXCC

LocationProvider wraps Core Location for one-shot fixes, continuous follow, and true-north heading (used by the compass screens). It can optionally reverse-geocode each fix and publish the result, which the Grid Finder uses.

GeoEntityLookup turns a coordinate into a DXCC entity and administrative subdivisions using Apple's reverse geocoder plus an ISO-3166 → DXCC map. It normalizes the subdivisions to the names LoTW/TQSL expect: US state codes, county-designator stripping, Connecticut planning-region → legacy county (from a full town→county table), and the independent cities of Virginia, Maryland, Missouri and Nevada — disambiguated from same-named counties by a "county designator first" rule. DXCCData and DXCCNumericData provide the entity roster and ARRL numeric codes used across the app and by Tiny BASIC.

Radio & Doppler

Transponders come from SatNOGS (TransponderService) as TransponderRecords that classify themselves as linear/FM/beacon and expose passband centers. OrbitPredictor.dopplerFrequencies computes the RX/TX dial frequencies from range-rate.

Calibration follows the CardSat model: a single combined oscillator correction, measurable from either leg, folded only into the operator's receive dial (uplink sign-flipped on an inverting transponder) and never onto the DX station's dials. It is stored per satellite in preferences and applied on every Doppler screen. The Home Live Doppler card adds a passband tuning slider (linear transponders) and an expander with per-satellite calibration sliders that share this same value with the bulk Calibrations editor.

Data services

ServiceRole
GPServiceFetches General Perturbations elements from AMSAT's daily bulletin, a CelesTrak group, or a custom OMM-JSON URL. Honors CelesTrak's rate policy (at most one request per dataset every two hours, with back-off) and caches to disk for offline launches.
TransponderServiceDownloads and caches the SatNOGS transmitter database, keyed by NORAD id, so every catalog satellite shows its transponders offline.
FeatureEngine (space weather)Pulls solar flux / sunspot / Kp / A-index (hamqsl with a NOAA SWPC fallback) for the Space Wx and propagation screens.
PassAlarmServiceSchedules local UNUserNotifications for upcoming passes; a router opens Home when one is tapped.
AO7ServiceAO-7 A/B illumination-mode timing.

All fetches identify the app with a browser-style User-Agent where feeds require it, and network access is only ever for these public data sources.

Tools & Tiny BASIC

The Tools screen is data-driven: BenchTools.allTools is a list of tool definitions (id, category, fields), and a single compute function dispatches on the id. Adding a calculator means adding a definition and a case. DeepParityEngine also contains the full Tiny BASIC interpreter — a self-contained tokenizer/parser/VM with live satellite host variables, a 240×135 graphics surface, and a sandboxed file store — documented in detail on its own page.

Exports

ExportService renders PDFs with Core Graphics (pass schedules, site comparisons, and the printable OSCARLOCATOR overlays — base map, range circle, and path arc) and writes CSV and ICS (calendar) files; XLSXExportService writes spreadsheets. Everything is shared through the standard iOS share sheet.

Building it

  • Clone the repository and open OrbitDeckIOS.xcodeproj in a recent Xcode (iOS 17 SDK or later).
  • SatelliteKit is vendored in the repo as a local Swift package, so there is nothing to fetch — just build and run on a device or simulator.
  • The Info.plist is generated from build settings; the launch screen uses a LaunchBackground color in the asset catalog.
  • Location, compass, and reverse-geocoding features need a real device (the Simulator has no magnetometer and limited geocoding).
